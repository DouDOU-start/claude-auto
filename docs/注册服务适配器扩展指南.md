# 注册服务适配器扩展指南

注册流程采用“通用编排器 + 服务适配器（Provider）”的结构。通用层管理浏览器、代理、邮箱轮询、超时、结果输出和资源关闭；服务适配器只实现目标网站差异。

## 调用关系

```text
commands/register*.js
        ↓
core/registration-runner.js
        ↓
providers/<服务>/registration.js
        ↓
登录页、验证邮件、新用户引导、会话提取
```

批量注册直接调用 `runRegistration()` 并接收结构化结果，不再启动子进程或解析终端提示文字。

## 服务适配器接口

每个注册服务适配器需要提供以下基本信息和方法：

```js
{
  id,
  displayName,
  startUrl,
  pageUrlIncludes,
  profilePrefix,
  resultFilePrefix,
  verificationLabel,
  verificationPrompt,
  createProfile(options),
  resultProfile(profile),
  waitForLoginReady(cdp, context),
  submitEmail(cdp, email, context),
  sendVerification(cdp, email, context),
  verificationWasSent(result),
  validateVerification(value, email),
  completeVerification(cdp, value, context),
  completeOnboarding(cdp, context),
  extractSession(cdp, context),
  pollVerification(context),
  isManualActionError(error),
  isRetryableError(error),
  summarizeError(error)
}
```

`context` 中可包含注册资料、超时取消信号和邮箱账号等运行信息。服务适配器不应自行启动或关闭 Chrome、代理桥，也不应直接处理命令行参数。

验证内容使用通用的 `value` 表示，可以是链接、一次性安全码或其他服务特定内容。`verificationLabel` 和 `verificationPrompt` 用于命令行进度与交互提示。

为兼容旧适配器，通用编排器仍会回退调用 `validateVerificationUrl()` 和 `openVerification()`，新实现应使用通用方法名。

## Grok 实现

Grok 已按以下结构接入：

```text
src/providers/grok/
├── registration.js
├── login.js
├── mail.js
├── onboarding.js
├── profile.js
└── session.js
```

`src/providers/index.js` 已注册 `grokRegistrationProvider`。现有命令可以通过统一参数调用：

```powershell
npm run interactive -- --provider grok --email user@example.com --no-proxy
npm run auto-register-mail -- --provider grok --account "email----password----client_id----refresh_token" --no-proxy
```

Grok 配置继续放在统一的 `config/app.local.json` 中：

```json
{
  "mail": {
    "randomDomain": "example.com"
  },
  "registration": {
    "provider": "grok"
  },
  "providers": {
    "claude": {},
    "grok": {}
  }
}
```

Grok 使用 6 位字母数字邮箱安全码，邮件可能显示为 `ABC-123`；适配器会规范化为 `ABC123` 后通过真实键盘事件输入。资料提交后等待站点自行完成 Turnstile，若出现可见挑战则交给人工处理，不实现绕过。

接入新服务时应为邮件验证信息提取、服务适配器注册表、资料校验和错误分类补充单元测试。
