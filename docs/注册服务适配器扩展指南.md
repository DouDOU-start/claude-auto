# 注册服务适配器扩展指南

注册流程采用“通用编排器 + 服务适配器（Provider）”的结构。通用层管理浏览器、代理、邮箱轮询、超时、结果输出和资源关闭；服务适配器只实现目标网站差异。

## 调用关系

```text
commands/register*.js
        ↓
core/registration-runner.js
        ↓
providers/<服务>/registration.js
        ↓
登录页、验证邮件、新用户引导、会话提取
```

批量注册直接调用 `runRegistration()` 并接收结构化结果，不再启动子进程或解析终端提示文字。

## 服务适配器接口

每个注册服务适配器需要提供以下基本信息和方法：

```js
{
  id,
  displayName,
  startUrl,
  pageUrlIncludes,
  profilePrefix,
  resultFilePrefix,
  createProfile(options),
  resultProfile(profile),
  waitForLoginReady(cdp, context),
  submitEmail(cdp, email, context),
  sendVerification(cdp, email, context),
  verificationWasSent(result),
  validateVerificationUrl(url, email),
  openVerification(cdp, url, context),
  completeOnboarding(cdp, context),
  extractSession(cdp, context),
  pollVerification(context),
  isManualActionError(error),
  isRetryableError(error),
  summarizeError(error)
}
```

`context` 中可包含注册资料、超时取消信号和邮箱账号等运行信息。服务适配器不应自行启动或关闭 Chrome、代理桥，也不应直接处理命令行参数。

## 接入 Grok

后续接入 Grok 时建议增加：

```text
src/providers/grok/
├── registration.js
├── login.js
├── mail.js
├── onboarding.js
├── profile.js
└── session.js
```

完成实现后，在 `src/providers/index.js` 注册 `grokRegistrationProvider`。现有命令即可通过统一参数调用：

```powershell
npm run interactive -- --provider grok
npm run auto-register-mail -- --provider grok --account "email----password----client_id----refresh_token"
```

Grok 配置继续放在统一的 `config/app.local.json` 中：

```json
{
  "providers": {
    "claude": {},
    "grok": {}
  }
}
```

接入新服务时应为邮件链接提取、服务适配器注册表、资料校验和错误分类补充单元测试。
